The AI gateway

A builder that needs a model, an agent, a generator that asks for help, a fix-up pass, does not have to hold a model credential of its own. With the AI gateway, which arrived in builder protocol version 2, it sends the call to Studio. Studio runs it on the AI providers the organization configured under Settings > AI, and records the tokens.

This page is the contract. The cratis build run --ai studio option of the Cratis CLI implements it, and presents it to agents as the OpenAI and Anthropic APIs they already speak. See Run the Cratis builder locally. A builder that talks to Studio without the CLI implements the request below.

Why a gateway

Section titled “Why a gateway”
  • Usage is counted where the organization counts it. Every call lands in the organization’s usage under the provider and model that answered, beside the calls Studio makes itself.
  • Pooling and limits apply. The agent and provider pool the organization chose for code generation decide which model answers, and a provider that is rate limited stops being picked.
  • No credential on the builder’s machine. A build server, a container or a laptop needs only the builder’s own token.
  • Every builder gets it the same way. The protocol carries the call, so the packaged Cratis builder, the Axon builder, an Eventmodelers builder and a builder you write all use the same endpoint.

Agreeing to it

Section titled “Agreeing to it”

The gateway belongs to protocol version 2. A builder names 2 in the protocolVersions of its hello. When the agreed protocolVersion in the welcome is 2 or higher, the gateway is there. A builder that agreed version 1, because it or Studio is older, must not call it, and one that needs it should stop and say so rather than fall back to a credential of its own.

Ask for a completion

Section titled “Ask for a completion”

The call is made for a slice the builder holds, under the same credential and with the same refusals as a lease renewal: once the lease is lost, or the build was cancelled, the call is refused with 410 Gone. The body is at most 4 MiB.

Member Required Meaning
orderId yes The order being built
messages yes The conversation so far, at most 400 messages. A role is system, user, assistant or tool
messages[].text no The text of the message
messages[].toolCalls no On an assistant message: the tool calls the model made, each with an id, a name and arguments as an object
messages[].toolCallId with tool On a tool message: the id of the call the text answers
tools no The tools the model may call, at most 64: a name, a description and parameters as a JSON Schema object
maxOutputTokens no At most 32768. Defaults to 8192
temperature no Between 0 and 2

200 OK:

finishReason is stop when the model is done, toolCalls when it wants the builder to run the tools in message.toolCalls and ask again with their results, or length when the answer was cut at maxOutputTokens. usage is what the provider reported; a count the provider did not report is null. Studio does not stream: the answer comes whole.

The builder runs the tool loop. Studio never runs a tool for it, and never sees the project.

Status Body When
400 { "reason": "…", "problems": ["…"] } The request cannot be read. problems names each one
401, 403 { "reason": "…" } The credential is unknown, removed, declined or still awaiting approval, as everywhere in the protocol
410 { "reason": "…" } The builder does not hold that slice, or its lease is lost. Stop building
429 { "reason": "…" } The build has used its allowance. Stop it: asking again changes nothing for this order
502 { "reason": "…" } The AI provider could not answer. Ask again in a moment
503 { "reason": "…" } The organization has no AI provider configured. Ask a maintainer to configure one under Settings > AI

The allowance

Section titled “The allowance”

A build order may make a limited number of model calls and use a limited number of output tokens, all of its calls together. By default that is 1,000 calls and 4,000,000 output tokens, which is far more than a slice needs, and exists so that a builder that loops cannot spend an organization’s AI providers without end. A retry is a new order and starts with a fresh allowance. A Studio operator can change both limits in the BuilderAI configuration section (MaximumCalls and MaximumOutputTokens).

A builder that receives 429 should stop building that slice and report the build as failed with the reason Studio gave. The count is kept in memory, so a restart of Studio gives running builds a fresh allowance.

What Studio records

Section titled “What Studio records”

The call is attributed to the organization, as code generation, and counted in its AI usage in tokens and cost per provider and model. Studio does not keep the messages. The builder’s token is never part of a call to a provider, and no provider credential is ever sent to the builder.
