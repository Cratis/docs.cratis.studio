The builder protocol

A builder connects to Studio from wherever it runs: a laptop, a build server, a container in another cloud. It needs no inbound port and no SDK. It speaks plain HTTPS and JSON to one address per organization, and every request goes from the builder to Studio.

This page is the contract. The cratis build command implements it, and any other builder can implement it from this page. If you only want to use the Cratis CLI, read Use the reference builder: cratis build instead.

The conversation

Section titled “The conversation”
  1. Register once. The builder creates its own token, sends it, and gets back its id and a short code.
  2. A maintainer approves the builder in Studio, under Settings > Builders, by typing the code the builder shows. Until then the builder builds nothing.
  3. Connect each time the builder starts. It names the protocol versions it speaks and what it can build. Studio agrees a version or refuses with the reason.
  4. Ask for work. Studio holds the request open until a slice is the builder’s to build, or answers that there is none yet.
  5. While it builds, the builder renews its lease with a heartbeat. When it is done, it reports one outcome.

The address

Section titled “The address”

<organization> is the organization’s name in Studio. The Connect a builder panel in Studio shows the full address. Every path below is relative to it.

Every request and answer is JSON with camelCase members and camelCase enum names, the same shape as build orders and outcomes. Every answer carries Cache-Control: no-store.

Credentials

Section titled “Credentials”

A builder creates its own token before it registers. The token has at least 256 random bits, written as 43 to 512 characters of letters, digits, -, _, . and ~. URL-safe base64 of 32 random bytes is enough. The builder keeps the token itself, for example in the operating system’s credential store.

Studio never stores the token. It keeps only a one-way hash of it, so nothing Studio stores can be presented back to it. A lost token cannot be recovered, so register again.

Every request after registering carries the builder’s id and token:

Studio’s hosted address sits behind a proxy that removes Authorization from requests to this path. Send the same value in X-Studio-Builder-Credential: <builderId>.<token> as well; Studio reads it first when it is present, and the Cratis CLI sends both.

The credential belongs to one organization. A builder of one organization is unknown to every other.

Register

Section titled “Register”
Member Required Meaning
name yes What maintainers see, 1 to 100 characters
machine no The machine it runs on, up to 200 characters, shown to the maintainer who approves it
token yes The token the builder created

201 Created:

Show the code on the builder’s own machine and ask a maintainer to approve it in Studio before expires, which is 15 minutes. The code is not a secret on its own. Together with the address the request came from, which Studio shows beside it, it tells the maintainer that this builder is the one they started.

Status When
400 The body cannot be read. problems names each problem
404 There is no such organization
429 More than 10 registrations a minute from one address for one organization

Connect

Section titled “Connect”

The manifest says what the builder can build:

Member Meaning
stacks The stacks it writes, for people choosing a builder. Studio does not interpret them
parts backend, ui or both. At least one
sliceTypes The slice types it builds, as the build order names them. None means every type
screenplayVersions The Screenplay schema versions it reads. Studio writes version 1
contractVersions The build contract versions it reads. At least one. Only a builder that reads version 3 is handed removal orders
kit The kit or template it builds with, shown to people
gitHandling studioManaged, builderManaged or both. At least one. See Git handling

The protocol handshake

Section titled “The protocol handshake”

The protocol version says what the conversation on this page means. It is agreed once, when the builder connects:

  1. protocolVersions names every version the builder speaks.
  2. Studio picks the highest version both speak.
  3. A builder that names no versions is older than the agreement and speaks version 1. It is accepted while Studio still speaks version 1.
  4. When no version is shared, Studio refuses with 409 and says which side must be updated. Retrying sooner cannot change the answer. Wait a minute, or until the builder or Studio is upgraded.

Studio speaks protocol version 1 today.

200 OK means the builder is welcomed:

needsUpgrade is true when the agreed version is older than Studio’s newest. The builder still works and should tell its owner to upgrade. leaseSeconds is how long a claim holds without a heartbeat, so renew well inside it.

The refusals:

Status Body When
202 { "reason": "…", "code": "K7QF-2M9D" } The registration waits for approval. Keep showing the code and connect again in a few seconds
401 { "reason": "…" } Unknown builder, wrong token, or removed. Stop, and register again only if the owner asks
403 { "reason": "…" } The registration was declined or expired. Register again
409 { "reason": "…", "minimum": 1, "current": 1 } No protocol version in common
422 { "reason": "…", "problems": ["…"] } The manifest cannot be read

An unknown builder and a wrong token answer the same 401, so a caller learns nothing without the whole credential.

Ask for work

Section titled “Ask for work”

Studio holds the request open for up to waitSeconds while it looks for a slice that is this builder’s to build. Ask again as soon as it answers.

204 No Content means nothing yet.

200 OK means a slice is claimed:

order is a build order in the highest contract version both sides speak. The claim is already made. The slice is In progress and held by this builder.

A slice is offered to a builder only when all of these hold:

  • it is offered by the build loop and nobody holds it,
  • it is this builder’s: the slice is assigned to it, or it is not assigned and this builder is its application’s builder (see Choosing a builder),
  • the builder’s manifest covers the slice’s type, the part offered, Screenplay version 1, a shared contract version and the application’s Git handling.

A slice that no connected builder may take is not given to another one. It waits.

409 with a reason means the builder has not connected yet, or said goodbye on /disconnect since. Connect again.

A registration still waiting for approval answers 202, a declined or expired one 403, and an unknown or removed builder 401, as on /connect. The same holds for every call below.

Renew the lease

Section titled “Renew the lease”

200 OK with { "leaseExpires": "…" }. 410 Gone with a reason means the lease is lost: it ran out, the attempt passed its deadline, a person cancelled the build, or the slice is held by another builder. Stop building that slice and discard the work.

Report progress

Section titled “Report progress”

The body is a progress report in contract version 2 or later: the order, the step the builder is on, new log lines and the tokens used so far. People see it on the slice while the build runs. A report does not renew the lease, so keep sending heartbeats.

200 OK with { "recorded": true }. 400 with problems when the report does not follow the progress schema. 410 Gone with a reason when the builder no longer holds the build or its lease is lost, the same as for a heartbeat.

Report the outcome

Section titled “Report the outcome”

The body is a build outcome. 200 OK with { "settled": "built" }, or blocked, failed or nothingToDo. The slice’s status is set as the build loop describes.

Status When
400 The outcome does not follow the schema. problems names each problem
409 The lease is lost, or the outcome does not fit the build’s Git handling. reason says which. While the lease holds, a corrected outcome may be sent

Disconnect

Section titled “Disconnect”

204. The builder shows as offline until it connects again. A slice it holds keeps its lease until the lease runs out.

Git handling

Section titled “Git handling”

Each application chooses who does the repository work, under Settings > Building. A builder’s own setting, under Settings > Builders, overrides it for every build that builder does. The choice is fixed when a slice is claimed, and is handed to the builder in git.

Studio-managed (studioManaged) Builder-managed (builderManaged)
Branch Studio names it in git.branch The builder chooses
Commit message Studio writes it in git.commitMessage The builder chooses
Pull request Studio opens it from the branch, one per slice or per feature (git.pullRequests) The builder opens it, or does not
A built outcome must report commit, and branch if given must be git.branch. Never pullRequest At least one of commit, branch, pullRequest
Shown on the slice The branch and commit The reported commit, branch or pull request, linked

With one pull request per feature, Studio reuses the open pull request of the build’s branch. The branch name must then be the same for every slice of the feature, so it may not use {slice}, {part} or {attempt}.

Branch name and commit message are templates with the placeholders {application}, {module}, {feature}, {slice}, {part} and {attempt}. In a branch name, every value is written in lowercase with - between words. The defaults are studio/{feature}/{slice} and Build {slice} ({part}).

Studio never puts a repository credential in a build order, a prompt or a log. A builder that pushes uses credentials of its own.

Choosing a builder

Section titled “Choosing a builder”

Every application has a builder. It is Studio’s own until someone chooses another under Settings > Building. A person can assign a single slice to another builder from the slice’s menu. The slice’s assignment wins over the application’s builder, and clearing it returns the slice to its application’s builder. Only approved builders of the organization can be chosen. The menu shows why a builder cannot build the slice, and a slice whose builder is offline says it waits for that builder.

Revoking a builder

Section titled “Revoking a builder”

A maintainer removes a builder under Settings > Builders. Its next request with the same token answers 401. A slice it holds keeps its lease until the lease runs out, and is then offered again.
