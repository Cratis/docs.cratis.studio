Connect an AI agent over MCP

Studio exposes your organization’s models to AI agents over the Model Context Protocol (MCP). An agent that is connected can read your projects, event models, brainstorming boards and concepts, and change them. Ask it to add a slice and it adds the slice, instead of describing how you would.

MCP access is not read-only

An agent that signs in as you can change the organization’s models, not only read them, with the access you have. Connect only agents you trust with that. MCP security for maintainers explains what a connected agent can and cannot reach.

Before you start

Section titled “Before you start”
  • You need to be a member of the organization. The agent works with your access to it and cannot see another organization.
  • An MCP-capable client: Claude Code, an editor’s assistant, or any program that can talk to an MCP server over HTTP and sign in with OAuth.

Find the endpoint

Section titled “Find the endpoint”
  1. Open Settings > MCP.
  2. Read the Endpoint.

Select How to connect for a dialog that fills these snippets with the real address.

Other clients

Section titled “Other clients”

Cursor, VS Code, Claude Desktop custom connectors and any other client that supports a remote MCP server with OAuth need only the address. They find the sign-in from https://mcp.cratis.studio/.well-known/oauth-protected-resource/mcp. A client that can only send a fixed header or API key cannot connect: Studio does not issue static keys.

Scripts and CI

Section titled “Scripts and CI”

A script has no browser, and Cratis Identity has no unattended credential for a person, so unattended access is not available today. Run the work through a signed-in client.

Sign in

Section titled “Sign in”

The first time the client connects, it opens a browser window for Cratis Identity. Sign in, approve the access the client asks for, and choose the organization. The client keeps the access; there is nothing to copy or store, and no secret to rotate.

Check that it worked

Section titled “Check that it worked”

Ask your agent to run studio_whoami. It should answer with your organization’s name. Then ask it to list your event models. If it can, the connection works.

What the agent can do

Section titled “What the agent can do”

The agent gets Studio’s tools. The ones you will use most:

  • Read the model. List and read event models and brainstorming boards, find an item by name, and read the structure of a project.
  • Change the model. Create event models and brainstorming boards, add and move events, regions, sticky notes and chats, set a sticky note’s color, and add concepts, constraints, state machines and workflows.
  • Edit an event model in Screenplay. Open a session on an event model, read and propose typed edits in Screenplay, and apply the accepted result to the board.
  • Read board findings. Get what the board’s checks report: compiler errors and the gaps in the model.
  • Export context. Hand a slice, a feature, an event model or a domain to a coding agent as Markdown, JSON, YAML or TOON. See Agent context.
  • Reach everything else. A catalog of every Studio command and query lets an agent do anything that has no named tool.

MCP tools and command catalog lists every tool.

What the agent cannot do

Section titled “What the agent cannot do”
  • It cannot reach another organization. The organization is fixed by the access token you approved, not by anything the agent asks for.
  • It cannot widen its own access by asking.
  • It cannot remove a module whose slices have started: Studio refuses the removal unless every slice in it is still Not started.

Changes the agent makes show up on the board like anyone else’s, and in the board’s history.

If it does not work

Section titled “If it does not work”
What you see What to do
401 and no browser opens The client does not support OAuth for remote servers. Update it or use another.
401 after it worked The sign-in expired and could not be renewed. Authenticate again.
The sign-in says the resource is not known The people running Studio have not enabled the studio-mcp audience on Studio’s Cratis Identity. Ask them to follow the Cratis Identity hookup guide for operators.
The agent sees the wrong organization The sign-in is bound to the organization you chose. Remove the server and connect again, choosing the right one.
The organization’s old client ID and secret no longer work They were removed. Sign in as a person instead.

Take access away

Section titled “Take access away”

Access belongs to you and your client. To end it, remove the server from your client, or ask a maintainer to remove you from the organization.
